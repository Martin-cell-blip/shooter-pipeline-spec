# 第 5 步执行 Agent 定位

任务：将非结构化补丁说明翻译为可追溯、可校验的配置改动提案；不是设计平衡数值，也不是凭开发者注释猜数。

输入：包含 from/to 的原文补丁条目、构造的改动前快照、schema，以及无答案的提案格式规范。
输出：提案 YAML，逐条保留原文依据、字段路径、模式、from/to、方向声明、联动处置和对冲理由。无法映射的条目显式保留待审，不静默丢弃。

验收必须独立对照官方结构化金标，检查英雄、字段、模式、单位和 from/to 的完整集合；同时检测漏改、多改、重复条目及无关字段被修改。
仅检查提案列出的路径不足以验收：空提案或漏提条目也必须失败。
意图用于核对方向声明，不用于推出精确数值；歧义仍交由 REVIEW。
执行 Agent 不读取金标提案、补丁的结构化答案、现成报告或补丁后 baseline。输入快照需移除泄露补丁后值的 provenance.overrides/conflicts 等内容，来源审计信息留在评测侧；记录实际发送输入以便检查泄漏。

模型供应商采用 DeepSeek；从 DEEPSEEK_API_KEY 读取密钥。Windows 用户级变量可能尚未继承到当前进程，需在进程内读取，不打印、不落盘。
模型 ID、参数、调用时间、输入哈希、原始输出、用量和校验结果在实跑时记录；密钥不进入记录。此文件确定契约；实现见 `pipeline/agent.py`（输入快照已剥离整个 provenance 段；实际发送的输入与原始回复存于 `runs/`），验收见 `pipeline/compare.py`（官方金标每条改动都必须被命中，空提案或漏条即失败）。首轮实跑记录见 `docs/RUN_LOG.md`。
